# 项目 CRUD 生成

## 输入与边界

先确认目标数据模型、输出范围和目标模块，再定位仓库级指令、现有生成器、模板、配置、同类 CRUD 和执行文档。不得假定项目存在特定生成器，也不得自行安装依赖或把手写代码冒充生成结果。

## 工作流

1. 检查工作树并记录已有修改，确认生成行为可能创建、覆盖或删除的文件范围。
2. 从项目规则和同类实现判断需要哪些模型、传输对象、持久化、业务服务、接口及测试骨架，不机械生成项目未使用的层次。
3. 项目已有生成器或明确要求生成器优先时，使用文档化的版本、配置和仓库级命令；先检查参数和目标路径，禁止任意参数透传或盲目覆盖。
4. 项目没有既有生成机制时，不得自行引入新工具。若是否允许按现有模式手写标准骨架不明确，必须先询问。
5. 将脚手架输出作为起点，按项目规则审查包路径、命名、公共契约、查询边界、事务、异常、校验和权限，再做必要业务改造。
6. 对比生成前后差异，移除占位内容和无关输出，保留用户已有修改，并运行受影响模块的编译、静态检查和测试。

## 组合与交付

- 涉及 DDL、迁移或 ORM 映射时，组合使用 `common-db`。
- 涉及 Java 输出时，组合使用 `common-java`。
- 交付时说明使用的生成机制、生成范围、后续改造、验证结果和未执行步骤。
