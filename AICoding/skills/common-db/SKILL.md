# 项目数据库设计

## 输入与边界

先确定仓库根目录、目标数据库对象和变更目的，再定位仓库级指令、数据库规范、迁移工具配置、Schema 来源及相关设计文档。不得把本 Skill 当作项目 DDL 规则源，也不得自行发明公共字段、默认值或表结构例外。

## 工作流

1. 检查工作树、目标目录、构建与迁移工具、数据库方言及已有同类表，使用精确表名或字段名读取必要片段。
2. 确认项目中初始化脚本、增量迁移、ORM 模型、生成 Schema 和设计文档各自是否为权威来源，避免修改非权威副本。
3. 从项目规则和既有表中确定命名、字段顺序、类型、默认值、约束、索引、注释、字符集、租户、审计及删除策略。
4. 按项目约定同步所有必须联动的 Schema、迁移、模型和文档；发现来源冲突时先明确冲突，再以可执行实现和项目契约复核。
5. 使用项目已有数据库工具验证语法或迁移结果，并检查差异是否包含字段丢失、顺序漂移、重复定义或无关格式变化。

## 缺失约定

项目未定义 DDL 约束时，优先沿用同领域最近的已验证模式。若选择会影响数据兼容、租户隔离、审计、安全或公共契约，必须先询问，不能把某个项目的惯例提升为通用默认值。

## 组合与交付

- 任务还包含 Java 修改时，组合使用 `common-java`。
- 任务需要标准 CRUD 时，组合使用 `common-crud`。
- 交付时说明权威 Schema 来源、联动文件、采用的项目规则、验证结果和未解决冲突。
