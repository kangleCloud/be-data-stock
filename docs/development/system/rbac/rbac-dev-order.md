# RBAC 开发顺序

## 1. 总体策略

RBAC 一期不要从“给所有 controller 加注解”开始，而要按“先把判定数据查出来，再让框架消费”的顺序推进。

推荐顺序：

1. 模型与接口对齐
2. RBAC 聚合查询
3. 登录态初始化
4. `Sa-Token` 回调接入
5. 控制器落注解
6. 菜单与按钮联调
7. 数据权限预留

---

## 2. 分阶段开发顺序

### 阶段一：模型与边界对齐

目标：

- 确认 RBAC 一期使用的表、字段、状态语义、超管语义
- 明确 `sys_user.is_super_admin` 是超级管理员唯一来源

输出：

- RBAC 设计文档定稿
- 返回模型和 Session key 设计定稿

验收：

- 设计文档无字段名冲突
- 登录、菜单、权限、角色、数据范围边界清晰

### 阶段二：RBAC 聚合查询能力

目标：

- 从数据库拿到用户的角色码、权限码、菜单集合

建议工作项：

- 在 user-role / role-permission / role-menu 相关 service 中完成 RBAC 聚合编排
- 单表查询、投影、去重和排序细节下沉到 mapper
- 数据库 SQL 不使用 `join`，统一采用“先查关联 ID，再查目标表”模式
- 由 `IAuthCommonService` 统一承接聚合查询
- 做统一过滤：`status = 1`、`is_deleted = 0`

输出：

- `getRoleCodesByUserId`
- `getPermissionCodesByUserId`
- `getMenusByUserId`
- `isSuperAdmin(userId)` 用户维度判定

验收：

- 给定用户 ID，可在 service 层拿到完整 RBAC 聚合结果
- 角色模块可独立提供角色分页、角色选择框、用户授权/取消授权能力

### 阶段三：认证上下文初始化

目标：

- 将 RBAC 聚合结果接入当前登录态

建议工作项：

- 在 `/auth/info` 中构建当前用户的角色、权限、菜单上下文
- 将角色码、权限码写入 Sa-Token Session

输出：

- 聚合型权限初始化接口
- Redis 缓存 权限/角色信息

验收：

- 登录后调用初始化接口，可得到当前用户的角色码、权限码、菜单树

### 阶段四：`StpInterfaceImpl` 接入

目标：

- 让 Sa-Token 真正消费当前用户的角色和权限集合

建议工作项：

- 实现 `getRoleList`
- 实现 `getPermissionList`
- 加入 Session 命中优先、DB 回源兜底逻辑

输出：

- 可工作的 `StpInterfaceImpl`

验收：

- `@SaCheckRole`
- `@SaCheckPermission`

在示例接口上可以正确拦截

### 阶段五：管理端控制器权限落地

目标：

- 将 RBAC 从“能力具备”推进到“业务接口实际受控”

建议工作项：

- 覆盖全部 `/system/*` 控制器，而不是只挑试点
- 只读接口统一使用 `view`
- 写接口统一使用 `add/update/delete`
- 角色授权接口统一使用 `system:role:grant`
- 清理 `SysOperLogController`、`SysLoginLogController` 的对外 `add/update`

输出：

- 全量受控的 `/system/*` 控制器
- 权限码命名规范

验收：

- 普通用户无法越权调用受控接口
- 超级管理员可正常访问
- 日志管理接口只剩读和删

### 阶段六：前端菜单与按钮联调

目标：

- 让前端基于后端返回数据完成页面级权限控制

建议工作项：

- 输出菜单树
- 输出权限码列表
- 约定按钮显隐规则

输出：

- 当前用户菜单树
- 权限码列表

验收：

- 用户看到的菜单与其角色一致
- 按钮显隐与接口鉴权结果一致

### 阶段七：数据权限预留与二期规划

目标：

- 不在一期实现复杂 SQL 裁剪，但要把扩展点留好

建议工作项：

- 统一 `data_scope_type` 的枚举与说明
- 预留 service 层数据范围解析入口
- 梳理哪些查询将来要接数据权限

输出：

- 数据权限扩展文档
- 二期改造清单

验收：

- 后续可以在不推翻一期 RBAC 的情况下平滑接入数据权限

---

## 3. 建议里程碑

### 里程碑 M1：权限基础闭环

- 阶段一
- 阶段二
- 阶段三

完成标准：

- `/auth/info` 可返回完整初始化数据

### 里程碑 M2：后端鉴权生效

- 阶段四
- 阶段五

完成标准：

- `Sa-Token` 注解鉴权生效
- `/system/*` 接口全部按 RBAC 受控

### 里程碑 M3：前后端权限联动

- 阶段六
- 阶段七

完成标准：

- 菜单、按钮、接口形成一致权限体验
- 数据权限具备下一阶段接入条件

---

## 4. 不建议的开发顺序

以下顺序会导致返工或边界混乱：

- 先给所有 controller 加 `@SaCheckPermission`，再回头补角色权限查询
- 先做数据权限 SQL 拼接，再补角色与权限基础聚合
- 登录时直接把所有菜单树、权限树都塞进 token
- 前端先写死权限码，后端再补编码规范

---

## 5. 最小可上线顺序

如果要压缩一期范围，最小上线顺序建议为：

1. 聚合查询角色/权限
2. 实现 `StpInterfaceImpl`
3. 接入 `/auth/info`
4. 给关键接口加权限注解

这个顺序可以最快让 RBAC 从“有表”变成“能拦截”。
